## First installation

Download the matching file and open it. Follow the device's installation steps. The single Android file also updates earlier phone-specific APKs. Keep the earlier app installed and keep its saved records when updating.

The Windows installer has no verified Windows publisher certificate yet, so Windows may show an unknown-publisher notice. Stop if you are unsure about the download. Installation and device permission decisions remain yours.

The Windows app includes its required runtime and document readers. You do not need to install the development tools. Worker records and login details are kept outside the installed app. On the creator's existing PC the app uses the previously saved record location; new computers start with an empty local record store.

## App updates

Both apps check this project's update notice when they open. A newer version shows **Update now** and **Update later**. Update later opens the current app and does not download or install an update. A missed or unavailable update check also lets you continue.

Update now downloads the matching installation file and checks it before opening the device's installation page. You finish the installation yourself. Saved records, account details and phone drafts are kept. Android may ask you to allow app updates from Worker Demand in its settings. The phone also has **Check app updates** on its home screen.

Version 1.2.0 and newer can find this update when they open. Older versions need a manual installation once. Choose Update now and finish the device's installation steps, or choose Update later to keep using the current version.

## Set up and send a request

1. The DEO opens the desktop app and signs in with Google. Additional DEO Google accounts currently need to be added to the sign-in test-user list before they can use it.
2. In **Data Entry**, choose the current Panchayat and Financial Year, download every offered Village and use **Verify filter data** to check workers through the official signed-in desktop browser.
3. In **Work Demand Requests**, find **Panchayat Secretary login codes** and choose **Create login code**. Select the area and Financial Year. Choose one Village for its own code, or All Villages for a Panchayat code. Enter 4 to 32 letters or numbers, or leave the code blank to generate six digits. Choose **Save code**, then give the code privately to the assigned Secretary. Each assignment uses its own code, including assignments in the same Block.
4. Use **View code** to read a current code saved on this computer. Use **Edit code** to change that assignment's year or code, or disable its code. Earlier codes cannot be recovered unless a protected copy was saved; set one once to save it on this computer.
5. The Secretary enters the code in Worker Demand. They see only their assigned shared workers. Aadhaar availability, ABPS and eKYC show **Verified**, **Pending**, **Not available** or **Unknown**. ABPS is the Aadhaar-Based Payment System. eKYC is an electronic identity check. **Refresh statuses** reads the latest details shared by the DEO and keeps selected workers. Pending or unknown verification answers allow the list to be sent for DEO review. The same statuses appear before Submit. Other saved checks and this year's workdays remain available. Days left belong to the whole Job Card family.
6. Use **Worker filters** to find active or inactive members, members with no work this year or a particular check status. Choose workers, select **Work Code / Work Order**, choose **Start Date** and optionally enter the number of workdays. The chosen family members share the available day limit. Review the names and choose **Submit request**. **Pending review** means the online service confirmed receipt. An offline waiting copy has not reached the DEO yet.
7. The assigned DEO receives the list under its correct Panchayat. Review the Work Order, application date, each worker's dates and days, and current worker checks in **Work Demand Requests**. Complete any days left blank on the phone before approval. Every included Village must pass its checks. **Submit to VBGRAMG** uses the existing desktop browser process. The phone receives the changed status when connected.

Google Forms is not used. Keep official portal login details on the office PC. Final official **Submit** stays under the DEO's control. Check **View Demand Details** and save the official result before marking a request Completed.

## Before regular office use

Check one agreed request on the intended Secretary phone and DEO computer. Confirm the assigned workers, work list, worker checks, day balances, optional days, desktop receipt and a reviewed status returning to the phone. Keep final government submission separate from that check.

The desktop's area lists now handle the portal's added report-link wording. For new installations, Data Entry, Job Card Records, Work Demand Sheet and My Areas start in Other Menus. Settings can show, hide and group optional menus. Work Demand Requests, Browser and Settings stay available. Aadhaar Authentication, Aadhaar Seeding and Photo start OFF; Aadhaar Availability stays required. ABPS and eKYC start ON. Existing saved choices are kept.

Read KNOWN-LIMITS.md for checks that still need attention before regular office use.

The GitHub repository contains installation files, instructions and update information. The project source files stay on the creator's PC. The downloads do not contain the creator's worker database, private passwords, Secretary codes or signing keys.
